# 내 냉장고를 부탁해

> 냉장고 속 재료와 유통기한을 보고, **먼저 써야 할 재료로 오늘 해 먹을 메뉴**를 정해 주는 웹앱

삼일회계법인 2026 Discover 신규입사자 연수 · 바이브코딩 팀 미션 **F-2조** 결과물이에요.
요리명을 검색하는 앱이 아니라, 내 냉장고 상황에 맞춰 메뉴를 **결정해 주는** 앱이에요.

- **바로 써 보기:** https://f2-naengbu.vercel.app
- 설치·로그인 없이 링크로 열리고, 휴대폰(390px 기준)과 PC 모두에서 동작해요.

---

## 누구를 위한 앱인가요

| 구분 | 내용 |
|---|---|
| 누가 | 자취 1~3년 차, 요리 초보 |
| 언제 | 장을 본 직후 / 저녁 메뉴를 고민하며 냉장고를 열었을 때 / 배달 앱을 켜기 직전 |
| 왜 | 재료는 있는데 조합법을 모름, 장을 더 보기 아까움, 매번 같은 메뉴 반복, 재료를 썩혀서 버림 |

## 화면과 주요 기능

| 화면 | 할 수 있는 일 |
|---|---|
| **S-01 내 냉장고** | 재료를 채소 칸 · 단백질 칸 · 문 선반에 나눠 보여 줘요. 타일마다 D-day와 **신선도 바**(남은 일수 ÷ 14일)가 있고, 기한 지난 재료는 흐리게 + 빨간 테두리로 표시해요. 요약 줄에 "3일 안에 먹어야 할 재료"와 "기한 지난 재료"를 따로 알려 줘요. |
| └ 재료 넣기/빼기 | **직접 입력**: 재료 칩을 눌러 넣고 빼요. **영수증 첨부**: 사진을 올리면 브라우저 안에서 그림자·대비를 보정한 뒤 글자를 읽어(OCR) 재료를 찾고, **확인 목록에서 이름·유통기한을 고치거나 뺀 뒤 승인해야** 냉장고에 들어가요. 빠진 재료는 입력칸을 눌러 후보에서 고르거나 직접 써서 추가해요. |
| **S-02/03 오늘의 추천 레시피** | **임박 재료로** 또는 **고른 재료로** 추천받아요. 카드마다 재료 칩(내 재료 / 냉장고에 있음 / 없음), 조리 방법, 추천 이유, 꿀조합 팁(예시)이 있어요. [이 요리로 해 먹었어요]를 누르면 쓴 재료만 냉장고에서 빠지고(양념은 그대로), 되돌릴 수 있어요. |
| **S-04 피드백 선택** | "매운 건 싫어요", "조리 시간이 너무 길어요" 등 6가지 중 여러 개를 골라요. |
| **S-05 재추천** | 피드백을 반영해 새 카드 3장을 골라요. 조건에 맞는 게 없으면 조건을 조금 풀어서 추천하고, 그래도 없으면 이전에 추천한 레시피를 보여 줘요. [이전 레시피로 돌아가기]로 직전 단계로 돌아갈 수 있어요. |

처음 열 때는 냉장고 문이 열리며 재료가 튀어나오는 시작 화면이 나와요(탭을 처음 열 때만, 누르면 건너뜀).

## 추천은 어떻게 하나요 (AI API 없이 규칙 기반)

발표 당일 300~400명이 동시에 접속해도 서버·API 키·비용 없이 즉시 응답하도록, 추천은 모두 `js/logic.js`의 규칙으로 계산해요.

1. **노출 조건** — 필요한 재료의 절반 이상, 그리고 2개 이상을 가지고 있어야 해요(밥·물·식용유는 집에 있다고 봐요). 임박 모드에서는 3일 이하 재료가 1개 이상 들어가야 해요.
2. **정렬** — 카드에 쓰이는 내 재료마다 남은 일수로 점수를 매겨 더해요(1일 이하 8점, 2~3일 4점, 4~7일 2점, 8일 이상 1점). 같으면 보유 비율 → 조리시간 → id 순.
3. **재추천** — 피드백을 조건으로 바꿔 후보를 걸러요(비평 기반 추천). 결과가 없으면 정해진 순서로 조건을 하나씩 풀고(매운맛 조건은 끝까지 지켜요), 3장 안에서 요리 종류가 겹치지 않게 골라요.

근거 자료와 자세한 순서는 [`docs/plan.md`](docs/plan.md) 4장에 있어요.

## 데이터

- **레시피 131개** — 팀이 작성한 39개 + 식품의약품안전처·농림축산식품부 공공데이터 92개(자취방에서 하기 어려운 요리는 걸러 내고 "~해요"체 4단계로 다듬음, `source`에 원본 id 기록)
- **마스터 재료 57종** — 재료 이름은 이 표기만 써요
- **꿀조합 팁** — 실제 사용자 글이 아니라 팀이 작성한 **예시 데이터**예요. 좋아요는 각자 기기 화면에서만 반영돼요.
- 냉장고 재료는 이 기기의 브라우저(localStorage)에만 저장되고, 영수증 사진은 기기 밖으로 보내지 않아요.

## 기술

- 바닐라 HTML · CSS · JavaScript (프레임워크·빌드 도구 없음)
- 외부 라이브러리는 CDN으로만: Pretendard · Noto Serif KR(글꼴), Lucide(아이콘), Tesseract.js(영수증 OCR, 인식 버튼을 누를 때만 불러옴)
- 로그인 · 외부 DB · 외부 API 없음 → GitHub `main`에 올리면 Vercel이 정적 파일로 자동 배포
- 테스트: Playwright (로직 단위 테스트 + 화면 스모크 테스트)

## 직접 실행하기

빌드가 필요 없어요. 저장소를 받아서 `index.html`을 브라우저로 열면 바로 동작해요.

```bash
git clone https://github.com/sonjong980304-tech/f2-naengbu.git
cd f2-naengbu
# index.html을 더블클릭하거나, 같은 와이파이의 휴대폰으로 보려면:
python -m http.server 8080
```

## 테스트

테스트 도구는 `tests/` 폴더 안에만 있어요(저장소 루트에는 package.json이 없어요).

```bash
cd tests
npm install
npx playwright install chromium
npx playwright test
```

- `tests/logic/` — D-day·배지·정렬·노출 조건·재추천·영수증 매칭 등 로직 단위 테스트("오늘" 날짜를 고정해서 언제 돌려도 같은 결과)
- `tests/tools/ocr-bench/` — 가짜 영수증 30장으로 OCR 인식률을 재는 개발용 도구 (`node tools/ocr-bench/bench.js before after`, 인터넷 필요)
- `tests/smoke/` — 화면 열림, 콘솔 오류 없음, 375px·1280px 가로 스크롤 없음, 화면 1→2/3→4→5 흐름 등

## 데이터를 고칠 때

앱은 `data/*.json`이 아니라 같은 내용의 `data/*.js`(window 전역 변수)를 불러와요. index.html을 파일로 직접 열어도 동작하게 하려는 방식이에요.

1. `data/*.json` 원본을 고쳐요.
2. `cd tests && node tools/sync-data.js`로 `data/*.js`를 다시 만들어요.
3. 테스트를 돌려요. 둘이 어긋나면 `data-sync` 테스트가 알려 줘요.

## 폴더 구조

```
/
├── index.html      앱 진입점 (화면 1~5)
├── css/app.css     디자인 토큰 + 화면 스타일
├── js/logic.js     추천 로직 순수 함수 (window.Logic)
├── js/receipt.js   영수증 글자 → 재료 매칭 순수 함수 (window.Receipt)
├── js/ocr.js       영수증 사진 보정 (window.ReceiptOCR)
├── data/           copy · recipes · sample-fridge · icon-map · ingredient-info (.json 원본 + .js)
├── icons/          ingredients/ 재료 아이콘 PNG 57개, svg-source/, CREDITS.txt
├── docs/           plan.md(계획) · DESIGN.md(디자인 규칙) · prompts.md(AI 활용 기록) · reference/
├── tests/          Playwright 테스트
└── CLAUDE.md       이 저장소에서 작업하는 Claude Code 규칙
```

`docs/`, `tests/`, `CLAUDE.md`, `README.md`는 `.vercelignore`로 배포에서 빠져요.

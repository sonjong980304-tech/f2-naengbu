### [추천 로직 logic.js + AI 없는 재추천]
- 담당자:
- 사용 AI: Claude Code (Opus 5.5)
- 프롬프트 초안: "기획안 참고해서 보완할 것들을 계획해 줘" → 계획서 검토 후 "AI 없는 추천방안은 그걸로 실행해줘"
- 결과(Before): 통합 시안 v1.3은 카드를 유통기한 순으로 정렬했고(기획안 2-2 점수 합과 불일치), 화면 5는 AI 응답을 흉내 내는 목업(1.8초 지연, `?fail` 실패 상태)이었음. 추천 함수가 화면 코드 안에 섞여 있어 테스트할 수 없었음
- 프롬프트 수정본: "정렬은 점수 합(기획안 2-2)으로, 동점은 보유 비율 → 조리시간 → id. 재추천은 AI 대신 비평 기반 + 조건 완화 + 종류 다양화로. 완화 순서는 절반 조건 → 종류 → 시간 → 난이도 → 재료 수, 매운맛은 풀지 않음"
- 수정 이유: 300~400명 동시 접속에서 API 키·서버·비용 없이 즉시 응답해야 하고, 같은 입력에 같은 결과가 나와야 TDD로 검증할 수 있음. 추천 시스템 연구(비평 기반 추천 Chen & Pu 2012, 제약 기반 추천 Felfernig & Burke, MMR 다양성 Carbonell & Goldstein 1998)를 근거로 선택 (docs/plan.md 4장)
- 결과(After): `js/logic.js` 순수 함수 17개로 분리. 화면 5 로딩 0.8초, 실패 상태 삭제, 결과가 없으면 조건을 하나씩 풀고 "조건을 조금 완화해서 추천했어요" 표시. 별로예요 레시피는 id로 누적 제외
- 검증 방법: Playwright 로직 테스트 31개(실패 확인 후 구현, 오늘 날짜 고정) + 스모크 테스트 3개(375px·1280px 가로 스크롤 없음, 콘솔 에러 없음, 화면 1→2/3→4→5→다시 피드백 흐름, 화면 순서가 logic.js 결과와 일치) 모두 통과. 기획안 예시(대파 D-2·두부 D-3·김치 D-20 → 두부김치 9점 1위) 테스트로 확인

### [피드백 반영: 신선도 바 · 민트 2단계 · 기한 지난 타일]

- 사용 AI: Claude Code (Opus 5.5)
- 프롬프트 초안: (받은 피드백 그대로) "D-day 알약을 남은 기간 바로 바꾸기(당근 14일 중 9일 → 64%). 초록을 2단계로: 배경 아주 옅은 민트 #F4FAF6, 카드는 흰색에 그림자 살짝, 진한 초록 #16A34A는 강조할 때만. 기한 지남은 카드 투명도 60% + 빨간 테두리"
- 결과(Before): 타일에 D-day 숫자 알약만 있어 신선도를 비율로 알 수 없음. 바탕과 카드가 둘 다 연두색이라 경계가 흐림. 기한 지난 재료는 배지만 빨강
- 프롬프트 수정본: Claude가 두 가지를 확인하고 진행 — ① #16A34A 위 흰 글자는 대비 3.3:1이라 버튼은 #15803D(5.0:1), #16A34A는 선택 테두리·체크·바에만 ② 데이터에 전체 보관 기간이 없어 "넣은 날 ~ 유통기한"을 전체 기간으로 쓰고, 샘플 냉장고에 shelfDays 추가
- 수정 이유: 피드백의 색을 그대로 쓰면 버튼 글자가 읽기 어려워짐(접근성). 신선도 비율을 계산하려면 전체 기간이 필요함
- 결과(After): 타일에 `D-9` + 얇은 신선도 바(채움 = 남은 일수 ÷ 전체 보관 일수, 색은 D-day 규칙). 바탕 민트 #F4FAF6 / 카드 흰색 + 옅은 그림자. 기한 지난 타일은 내용 60% + 빨간 테두리. 재료에 넣은 날짜(addedDate) 저장, 비율 계산은 `Logic.freshnessPercent`(TDD). 외부 CDN 일시 오류로 테스트가 깨지지 않게 스모크 테스트는 로컬 파일 로딩 실패만 잡도록 수정
- 검증 방법: 로직 테스트 3개 추가(64%, 기한 지남 0%, 경계값), 스모크 테스트 1개 추가(당근 바 64%, 대파 날짜를 어제로 바꾸면 흐림·빨간 테두리·0%). 전체 45개 통과, 390px 스크린샷 확인
